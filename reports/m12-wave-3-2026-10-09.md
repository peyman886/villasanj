owner's two additions of 2026-10-09: search filters after HomeToGo and jabama, and a design pass
with the Taste Skill set.

## Taste Skill set: installation and use

- `npx skills add Leonxlnx/taste-skill` had installed 14 skills into `~/.agents/skills`, which
  Claude Code does not read. They were linked into `~/.claude/skills` (symlinks, nothing copied or
  changed) and then appeared in the session's skill list.
- Read and applied: `design-taste-frontend` (main skill; brief inference, dials, pre-flight check)
  and `redesign-existing-projects` (audit-first rules). Not used, with reason: image-generation
  skills (no generated imagery: the product shows only real listing photos and OSM maps, D8.1 and
  D8.2), `industrial-brutalist-ui` and `gpt-taste` (aesthetic families that do not fit a trust-first
  price comparison), `brandkit` (no brand change requested).
- Design read: «redesign (preserve) of a Persian price-comparison product for travellers and a
  Torob reviewer; calm, trust-first language; Tailwind 4 + Vazirmatn + the existing green accent».
  Dials: VARIANCE 4, MOTION 3, DENSITY 5 (the skill's "redesign, preserve" and trust-first rows).
- Applied from the skill: one accent and a documented shape rule (pills for chips and filters,
  12 px controls, 16 px cards, 20 px dialogs); no em-dash or en-dash anywhere in the product or docs
  UI (the "—" placeholder became "-"); a dark mode (the skill's consumer-page requirement) built on
  the existing tokens; no `window` scroll listener (the section bar now uses an IntersectionObserver
  band); every JS scroll honours reduced motion; motion only where it says something (dialog
  opening, the photo pairs locking together, pin highlight); empty, loading and error states kept.
- Deliberately not applied, with reason: the icon library stays `lucide-react` (the skill allows an
  existing dependency and requires one family per project; switching would touch every page for no
  user gain); Vazirmatn stays (Persian text; the skill's font list is Latin-only); no image
  generation or stock photos (product rule: only real data and real photos).

## Search filters (owner's addition)

Chosen from what the catalog actually stores for every listing; nothing new is collected:

| Filter | Stored fact | Rule |
|---|---|---|
| Price, whole stay or per night | the listing's own offer (lower bound) | min/max on the lower bound |
| Rooms, capacity | `bedrooms`, `max_capacity` | at least N; unknown fails |
| Amenities (8) | amenity list, description, photos, map | the listing states it or the map/photos show it |
| Property type | `property_type` | any of the chosen |
| Platform, on both platforms | listing platform, ER villas | any of the chosen; multi-platform villas |
| Instant booking | `instant_booking` | true only |
| Rating | the platform's average | at least |
| Distance to the sea | measured range over the blur circle | the best case decides (as in the truth check) |

Interaction follows the references: «فیلترها» opens a panel (a dialog; a full-screen sheet on
phones) with quick tiles and their counts, the price spread as a histogram with a two-handle range,
steppers, checkbox grids with counts, choice chips, and a footer with «حذف همه» and a live
«نمایش N ویلا». Applied filters become removable chips next to the query's chips. The search is
always filtered on the server (`discovery.domain.filters`, after ranking, before one card per
villa; never re-ranking); the panel counts with the same rules in TypeScript, and both run the same
cases (`backend/tests/fixtures/filter_cases.json`). Measured: the panel promised 27 villas for
«رزرو آنی + تا ۱ کیلومتر از دریا» on the demo query; the search returned 27.

## Decisions made in this wave

- Filters narrow the ranked results and never re-rank; requested features in the query still rank
  confirmed villas first (unchanged).
- A feature filter accepts what the listing itself says (amenity list or description) or what the
  map and photos show; it does not demand independent confirmation, which the truth check and the
  card's highlight already show.
- Distance to the sea uses the best case over the blur circle; a filter never drops a villa that
  could satisfy it. An unknown fact fails a filter that asks for it.
- The «پلتفرم» filter offers one platform at a time («فقط جاباما» / «فقط شب»); «در هر دو پلتفرم» is
  a separate quick filter, because that is the product's distinctive question.
- The ADR files (English documents the portal shows as written) keep their own punctuation; every
  string the product and the portal write themselves is free of em- and en-dashes.
