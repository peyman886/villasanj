## مدل زبانی کجا به کار می‌رود

| کار                       | مدل فعلی                       | پشتیبان               | چرا مدل، نه قاعده                        |
| ------------------------- | ------------------------------ | --------------------- | ---------------------------------------- |
| فهم پرسش                  | gpt-5.4-mini                   | gemini-3.1-flash-lite | فارسی آزاد؛ خروجی با محافظ عدد و نقل‌قول |
| داور تطبیق                | gemini-3.8-flash               | gpt-5.4-mini          | مقایسه‌ی بصری اتاق‌ها که hash نمی‌بیند   |
| خلاصه‌ی نظرها             | gemini-3.8-flash، reasoning کم | gpt-5.4-mini          | جمع‌بندی متن با ارجاع                    |
| توضیح «چرا این ویلا؟»     | gemini-3.8-flash، reasoning کم | gpt-5.4-mini          | نثر فارسی پیرامون اسلات‌ها               |
| استخراج ادعا (باقی‌مانده) | gemini-3.1-flash-lite          | gpt-5.4-mini          | جمله‌هایی که قواعد از پسشان برنیامدند    |

قاعده‌ی «اول قطعی»: اول regex، قواعد و pHash؛ مدل فقط باقی‌مانده را می‌بیند. gpt-5-nano عمداً کنار
گذاشته شد، چون در آزمون استخراج رد شد. embedding متن (ADR-0006) ساخته نشده است: بازیابی برداری تا
وقتی ارزیابی بازیابی (معیار ۲ از M8) برتری‌اش را نشان ندهد عرضه نمی‌شود. embedding تصویر هم محلی است
(DINOv2، ADR-0012).

<Steps>
  <Step title="مسیریابی">
    `RoutedLLMClient` برای هر کار اول مدل اصلی و بعد پشتیبان‌ها را امتحان می‌کند، فقط در خطای انتقال
    یا دسترس‌پذیری، و برای هر کار سقف هم‌زمانی دارد. مسیریابی بالای کش قرار دارد، چون کلید کش به مدل
    وابسته است: پاسخ مدل پشتیبان هرگز به جای مدل اصلی سرو نمی‌شود.
  </Step>
  <Step title="کش">
    کلید کش sha256 از provider، مدل، `prompt_id@version`، پیام‌ها (با hash تصویرها)، schema و
    پارامترهاست. هر تغییر در قالب prompt نسخه را بالا می‌برد و تستی hash قالب‌ها را چک می‌کند تا این
    کار فراموش نشود. هر برخورد کش هم یک سطر صفردلاری در دفتر هزینه دارد.
  </Step>
  <Step title="تلاش دوباره">
    backoff نمایی با jitter، با رعایت `Retry-After`. خروجی نامعتبر همراه بازخورد اعتبارسنجی دوباره
    پرسیده می‌شود. «سهمیه تمام شده» دوباره امتحان نمی‌شود.
  </Step>
  <Step title="کنترل هزینه">
    پیش از هر فراخوانی، بدترین هزینه‌ی ممکن رزرو و با بودجه‌ی کار و سقف پروژه (۳۰ دلار) مقایسه
    می‌شود. هر تلاش، حتی ناموفق، یک سطر در `ops.llm_call` است.
  </Step>
  <Step title="خروجی ساختاریافته">
    اعتبارسنجی Pydantic با json_schema سخت‌گیرانه. `finish_reason=length` روی مدل‌های reasoning خطا
    حساب می‌شود، نه پاسخ ناقص.
  </Step>
</Steps>

## برآورد پیش از اجرا

هر use case که از مدل زبانی استفاده می‌کند `plan()` دارد، پس `--dry-run` هزینه را بدون هیچ فراخوانی
برآورد می‌کند: برخوردهای کش کم می‌شوند و token و هزینه از برآوردگر کالیبره‌شده‌ی هر مدل و فهرست قیمت
می‌آیند. نمونه‌ها: برآورد خلاصه‌ی نظرها ۳٪ و برآورد خواندن ادعاها ۲۲٪ با دفتر هزینه فاصله داشت (معیار
±۲۵٪).

```bash
make dry-run JOB=llm-smoke                                       # قیمت یک کار با صفر فراخوانی
cd backend && uv run villasanj er judge --low -2 --high 3 --dry-run
cd backend && uv run villasanj llm spend                         # جمع دفتر هزینه و سقف
```

## واقعیت‌های حساب و مدل‌ها

- AvalAI در **tier 3** است (از headerهای `x-ratelimit-*`، ۹ مهر).
- Gemini برای هر تصویر، صرف‌نظر از اندازه، حدود ۱۰۹۰ token حساب می‌کند؛ برای همین داور یک شبکه‌ی
  ترکیبی از عکس‌ها می‌گیرد، نه تصویرهای جدا.
- `gemini-embedding-001` مصرف را صفر گزارش می‌کند؛ دفتر هزینه آن را «برآوردی» علامت می‌زند.
- gemini-3.8-flash به‌طور پیش‌فرض فکر می‌کند (۱۶۵ تا ۲۵۵ token reasoning حتی برای پاسخ ساده)؛ برای
  خلاصه و توضیح، `reasoning_effort = "low"` را اندازه گرفتیم و تنظیم کردیم.

## تست‌ها و حالت آفلاین

- **تست‌ها هرگز API واقعی را صدا نمی‌زنند:** `FakeLLMProvider` قطعی است و پاسخ‌هایش از پیش نوشته
  شده‌اند. تست‌های زنده نشان `live_llm` دارند، فقط با `make test-live` اجرا می‌شوند و سقفشان ۰٫۰۵
  دلار است.
- **دموی آفلاین:** `LLM__PROVIDER=offline` فقط از کش پاسخ می‌دهد؛ اگر پاسخی در کش نباشد، نتیجه ۵۰۳
  است و صفحه آن بخش را حذف یا جایگزین می‌کند.
- **کلید:** فقط در `.env`؛ هرگز در کد، لاگ، پیام خطا یا کامیت. `.env.example` مقدار ندارد و gitleaks
  در pre-commit اجرا می‌شود.

## افزودن provider تازه

یک adapter برای `RawModelProvider`، یک شاخه در `build_provider` و مقدار `LLM__PROVIDER`. نام مدل‌ها در
`config/llm.toml` می‌آید. تزئین‌کننده‌ها و use caseها تغییری نمی‌کنند.
