## کدام پلتفرم‌ها و چرا

پیش از اولین درخواست آگهی، robots.txt و شرایط استفاده‌ی هفت پلتفرم را خواندیم و بررسی کردیم (۹ مهر،
`docs/sources/README.md`، با hash هر سند):

| پلتفرم        | robots.txt                            | شرایط استفاده                                          | نتیجه                       |
| ------------- | ------------------------------------- | ------------------------------------------------------ | --------------------------- |
| جاباما        | همه‌چیز مجاز                          | درباره‌ی دسترسی خودکار بندی ندارد                      | خزش با محدودیت‌های ADR-0008 |
| شب            | صفحه‌ی آگهی مجاز؛ رزرو و پرداخت ممنوع | بند صریحی ندارد؛ تصمیم با مالک بود                     | خزش پس از تأیید مالک        |
| جاجیگا        | بیشتر مسیرها مجاز                     | بند ۱۰-۳ و ۱۰-۴: ربات، crawler و data mining ممنوع     | کنار گذاشته شد              |
| اتاقک         | `/api` و `/rooms-` ممنوع              | خزش و data mining ممنوع؛ استفاده از محتوا با مجوز کتبی | کنار گذاشته شد              |
| میهمانشو      | صفحه‌های عمومی مجاز                   | هر نسخه‌برداری بدون مجوز کتبی ممنوع                    | کنار گذاشته شد              |
| هومسا، میزبون | در دسترس نبودند                       | -                                                      | -                           |

نبودن منع در شرایط استفاده به معنای اجازه نیست؛ برای همین جاباما و شب هم با همان قیدها خزیده شدند:
فقط صفحه‌های عمومی بدون ورود، یک درخواست در هر سه ثانیه برای هر میزبان، توقف با هر نشانه‌ی
مسدودشدن، و بازنشر نکردن چیزی جز تصویر کوچک و خلاصه با ذکر منبع. <Adr n="0011" />

## خزش مؤدبانه

<Steps>
  <Step title="robots.txt پیش از هر URL">
    `PoliteFetcher` برای هر URL و هر hop تغییر مسیر، robots.txt را با protego چک می‌کند. از خود
    robots.txt هم snapshot گرفته می‌شود. طبق RFC 9309، پاسخ ۴xx به robots.txt یعنی «بدون محدودیت»؛
    این مورد برای `s3gw.shab.ir` (پاسخ ۴۰۳ از S3) ثبت و به مالک گزارش شد.
  </Step>
  <Step title="یک درخواست هم‌زمان برای هر میزبان">
    بین دو درخواست دست‌کم ۳ ثانیه فاصله با jitter، یا Crawl-delay اگر بیشتر باشد. روی ۴۲۹ و ۵xx
    backoff می‌کنیم و `Retry-After` را رعایت می‌کنیم.
  </Step>
  <Step title="توقف هنگام مسدودشدن">
    رگبار ۴۰۳ یا نشانه‌ی captcha پلتفرم را `BLOCKED` می‌کند و اجرا می‌ایستد. هیچ تلاش دوباره‌ای با
    header دیگر، proxy یا ابزار پنهان‌کاری در کار نیست؛ ادامه فقط با تصمیم مالک ممکن است (`crawl run
    … --after-block`).
  </Step>
  <Step title="معرفی خود">
    user agent نام ربات و راه تماس را می‌گوید (`CRAWL__CONTACT` در `.env`). cookie نگه نمی‌داریم.
    تنها شباهت به مرورگر، header استاندارد `Accept` است، چون جاباما بدون آن صفحه‌ای بدون آگهی
    برمی‌گرداند.
  </Step>
  <Step title="snapshot از هر پاسخ">
    بدنه، وضعیت، headerهای انتخاب‌شده (بدون cookie) و زمان دریافت، به‌صورت content-addressed در blob
    store ذخیره می‌شوند. حالت پیش‌فرض `CRAWL__MODE=offline` است و اجرای زنده پرچم صریح می‌خواهد.
  </Step>
</Steps>

## از snapshot تا کاتالوگ

parse تابع خالصی از snapshot است: adapter هر پلتفرم بدون I/O صفحه را می‌خواند و یک `ParsedListing`
برمی‌گرداند که زبان مشترک ingestion و catalog است. `make reparse` کل کاتالوگ را بدون حتی یک درخواست
شبکه از snapshotها دوباره می‌سازد؛ تستی که socket را مسدود می‌کند این را تضمین می‌کند، و دو بازسازی
پشت‌سرهم hash یکسان دارند.

داده‌ی آشفته‌ای که adapterها و یکدست‌ساز از پسش برمی‌آیند (هر مورد یک تست جدولی است؛ بیش از ۱۰۰
حالت):

- **واحد پول:** جاباما ریال منتشر می‌کند و شب تومان. هر adapter واحد پلتفرم خودش را می‌شناسد،
  `Money` همیشه ریال صحیح است و نمایش به تومان است.
- **«صفر یعنی تعیین‌نشده»:** جاباما برای قیمت آخر هفته، تعطیل، نفر اضافه و امتیاز از `0` به معنای
  «تعیین نشده» استفاده می‌کند. این مقدارها «نامعلوم» می‌شوند، هرگز رایگان یا امتیاز صفر.
- **تقویم:** API تقویم شب دو شکل پاسخ دارد و روزها را با ماه شمسی کلید می‌زند. شب‌های `disabled`
  جاباما نمی‌گویند رزرو شده‌اند یا بسته‌اند، پس «در دسترس نیست» ذخیره می‌شوند.
- **متن فارسی:** ی و ک عربی، ارقام فارسی و عربی، نیم‌فاصله و فاصله‌ها؛ یکدست‌ساز idempotent است و
  با property test چک می‌شود.
- **مکان:** فیلد محله‌ی جاباما همیشه خالی است؛ نام مکان‌ها با gazetteer دست‌چین
  `config/gazetteer.toml` (۱۱۷ مکان) resolve می‌شوند: فقط نام‌هایی که در داده دیده شده‌اند، بدون حدس
  زدن غلط املایی.

## برداشت هم‌زمان سناریوها

مقایسه‌ی دو پلتفرم فقط وقتی معنا دارد که تقویم و قیمت هر دو در یک بازه‌ی کوتاه دیده شده باشند.

## خط لوله‌ی عکس

<Diagram name="photo-pipeline" caption="از عکس پلتفرم تا شواهد تطبیق و برچسب‌های تصویری" />

- **فقط بایت‌های لازم:** برای هر آگهی پنج عکس پوشش یک بار و مؤدبانه دانلود می‌شود. هر عکسی که به
  کاربر نشان می‌دهیم مستقیم از CDN خود پلتفرم بار می‌شود، پس چیزی برای نمایش کپی نمی‌شود.
- **pHash و dHash** برای پیدا کردن کپی تقریباً یکسان و برای وزن «بسامد در سند»: عکسی که در چند آگهی
  آمده (مثلاً عکس تبلیغاتی یک مجتمع) وزن کمی می‌گیرد.
- **DINOv2-small محلی** برای شباهتی که در برابر برش مقاوم است. در benchmark روی ۸۷۲ عکس و ۶۰۰ پرسش،
  recall@1 برابر ۱٫۰ بود، در حالی که pHash برش ۷۰٪ را فقط در ۳۵٪ موارد پیدا کرد. embeddingهای API
  (gemini-embedding-2) همه‌ی کپی‌ها را پیدا کردند، ولی ویلاهای نامرتبط را هم شبیه‌تر دیدند (صدک ۹۹
  شباهت ۰٫۸۳ در برابر ۰٫۶۶). <Adr n="0012" />
- **یک بار محاسبه:** embedding برای هر جفت (hash محتوا، شناسه‌ی مدل) ذخیره می‌شود؛ اجرای دوباره چیزی را
  دوباره حساب نمی‌کند.
- **SigLIP 2** برای برچسب‌های صفر-نمونه (استخر، جکوزی، جنگل، باربیکیو، منظره‌ی دریا، شومینه)، با
  آستانه‌ای که برچسب‌های مالک تعیین می‌کنند. شرح در [راستی‌آزمایی](/docs/truth-check).

<Callout kind="info" title="چرا عکس‌های اصلی شب">
  تصویرهای کوچک شب برش ۴:۳ هستند و برای عکس‌های عمودی pHash را می‌شکنند (فاصله‌ی ۲۰ تا ۳۲ بیت). پس
  عکس اصلی شاهد تطبیق است، حتی اگر از قاعده‌ی «حداکثر ۸۰۰ پیکسل» بزرگ‌تر باشد؛ این استثنا در
  ADR-0008 ثبت شده است.
</Callout>

## حریم خصوصی و بازنشر

- نام نظردهنده‌ها و شماره‌ی تلفن ذخیره نمی‌شود. نام میزبان فقط برای تطبیق به کار می‌رود.
- snapshotها و عکس‌ها هرگز وارد git نمی‌شوند. fixtureهای تست کوتاه‌شده‌اند و داده‌ی شخصی ندارند.
- رزرو همیشه روی خود پلتفرم انجام می‌شود؛ هر صفحه پیوند مستقیم به آگهی اصلی دارد.

## بازتولید

```bash
make crawl P=jabama            # پیش‌فرض: بازپخش snapshotها، بدون شبکه
make crawl P=jabama LIVE=1     # خزش زنده (CRAWL__CONTACT لازم است)
make crawl-status P=jabama     # وضعیت صف frontier
make reparse                   # بازسازی کاتالوگ و hash عکس‌ها از snapshotها
make crawl-metrics             # ترافیک هر میزبان با فاصله‌ی اندازه‌گیری‌شده
make report                    # پوشش سناریوها و resolve شدن مکان‌ها
```
