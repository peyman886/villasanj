## کجا مدل زبانی به کار می‌رود

| کار                       | مدل فعلی                       | پشتیبان               | چرا مدل، نه قاعده                             |
| ------------------------- | ------------------------------ | --------------------- | --------------------------------------------- |
| فهم پرسش                  | gpt-5.4-mini                   | gemini-3.1-flash-lite | زبان آزاد فارسی؛ خروجی با محافظ عدد و نقل‌قول |
| داور تطبیق                | gemini-3.8-flash               | gpt-5.4-mini          | مقایسه‌ی بصری اتاق‌ها که hash نمی‌بیند        |
| خلاصه‌ی نظرها             | gemini-3.8-flash، reasoning کم | gpt-5.4-mini          | جمع‌بندی متن با ارجاع                         |
| توضیح «چرا این ویلا؟»     | gemini-3.8-flash، reasoning کم | gpt-5.4-mini          | نثر فارسی دور اسلات‌ها                        |
| استخراج ادعا (باقی‌مانده) | gemini-3.1-flash-lite          | gpt-5.4-mini          | جمله‌هایی که قواعد نخواندند                   |

قاعده‌ی «اول قطعی»: regex، قواعد و pHash اول؛ مدل فقط باقی‌مانده را می‌بیند. gpt-5-nano عمداً کنار
گذاشته شد: در آزمون استخراج رد شد. embedding متن (ADR-0006) ساخته نشده است: بازیابی برداری تا وقتی
ارزیابی بازیابی (معیار ۲ از M8) برتری‌اش را نشان ندهد عرضه نمی‌شود، و embedding تصویر محلی است
(DINOv2، ADR-0012).

  </Step>
  <Step title="کش">

    پارامترها. هر تغییر قالب prompt نسخه را بالا می‌برد؛ تستی hash قالب‌ها را چک می‌کند تا فراموش
    نشود. هر برخورد کش هم یک سطر صفر دلاری در دفتر هزینه دارد.
  </Step>
  <Step title="تلاش دوباره">
    backoff نمایی با jitter و احترام به `Retry-After`. خروجی نامعتبر با بازخورد اعتبارسنجی دوباره
    پرسیده می‌شود. «سهمیه تمام شده» دوباره امتحان نمی‌شود.
  </Step>
  <Step title="حاکم هزینه">
    پیش از هر فراخوانی بدترین هزینه‌ی ممکن رزرو و با بودجه‌ی کار و سقف پروژه (۳۰ دلار) مقایسه
    می‌شود. هر تلاش، حتی ناموفق، یک سطر در `ops.llm_call` است.
  </Step>
  <Step title="خروجی ساختاریافته">
    اعتبارسنجی Pydantic با json_schema سخت. `finish_reason=length` روی مدل‌های reasoning خطاست، نه
    پاسخ ناقص.
  </Step>
</Steps>

## برآورد پیش از اجرا

هر use case مدل‌زبانی `plan()` دارد، پس `--dry-run` بدون هیچ فراخوانی هزینه را برآورد می‌کند: برخوردهای
کش کم می‌شوند و token و هزینه از برآوردگر کالیبره‌شده‌ی هر مدل و فهرست قیمت می‌آید. نمونه‌ها:
خلاصه‌ی نظرها ۳٪ و خواندن ادعاها ۲۲٪ با دفتر هزینه فاصله داشتند (معیار ±۲۵٪).

```bash
make dry-run JOB=llm-smoke                                       # قیمت یک کار با صفر فراخوانی
cd backend && uv run villasanj er judge --low -2 --high 3 --dry-run
cd backend && uv run villasanj llm spend                         # جمع دفتر هزینه و سقف
```

## واقعیت‌های حساب و مدل‌ها

- AvalAI **tier 3** است (از headerهای `x-ratelimit-*`، ۹ مهر).
- Gemini برای هر تصویر صرف‌نظر از اندازه حدود ۱۰۹۰ token حساب می‌کند؛ پس داور شبکه‌ی ترکیبی
  عکس‌ها را می‌گیرد، نه تصویرهای جدا.
- `gemini-embedding-001` مصرف را صفر گزارش می‌کند؛ دفتر هزینه آن را «برآوردی» علامت می‌زند.
- gemini-3.8-flash به‌طور پیش‌فرض فکر می‌کند (۱۶۵ تا ۲۵۵ token reasoning حتی برای پاسخ ساده)؛ برای
  خلاصه و توضیح `reasoning_effort = "low"` اندازه‌گیری و تنظیم شد.

## تست‌ها و حالت آفلاین

- **تست‌ها هرگز API واقعی را صدا نمی‌زنند:** `FakeLLMProvider` قطعی و از پیش نوشته‌شده. تست‌های زنده
  نشان `live_llm` دارند، فقط با `make test-live` اجرا می‌شوند و سقفشان ۰٫۰۵ دلار است.
- **دموی آفلاین:** `LLM__PROVIDER=offline` فقط از کش پاسخ می‌دهد؛ نبودن در کش یعنی ۵۰۳ و صفحه آن
  بخش را حذف یا جایگزین می‌کند.
- **کلید:** فقط در `.env`؛ هرگز در کد، لاگ، پیام خطا یا کامیت. `.env.example` بدون مقدار است و gitleaks
  در pre-commit اجرا می‌شود.
