## کدام پلتفرم‌ها و چرا

پیش از اولین درخواست آگهی، robots.txt و شرایط استفاده‌ی هفت پلتفرم خوانده و تحلیل شد (۹ مهر،
`docs/sources/README.md`، با hash هر سند):

| پلتفرم        | robots.txt                            | شرایط استفاده                                            | نتیجه                         |
| ------------- | ------------------------------------- | -------------------------------------------------------- | ----------------------------- |
| جاباما        | همه‌چیز مجاز                          | بندی درباره‌ی دسترسی خودکار ندارد                        | crawl با محدودیت‌های ADR-0008 |
| شب            | صفحه‌ی آگهی مجاز؛ رزرو و پرداخت ممنوع | بند صریحی ندارد؛ تصمیم با مالک بود                       | crawl پس از تأیید مالک        |
| جاجیگا        | بیشتر مسیرها مجاز                     | بند ۱۰-۳ و ۱۰-۴: ربات و crawler و data mining ممنوع      | کنار گذاشته شد                |
| اتاقک         | `/api` و `/rooms-` ممنوع              | crawl و data mining ممنوع؛ استفاده از محتوا با مجوز کتبی | کنار گذاشته شد                |
| میهمانشو      | صفحه‌های عمومی مجاز                   | هر نسخه‌برداری بدون مجوز کتبی ممنوع                      | کنار گذاشته شد                |
| هومسا، میزبون | در دسترس نبودند                       | —                                                        | —                             |

مجوز نداشتن از شرایط استفاده با «مجاز بودن» یکی نیست؛ برای جاباما و شب هم همان قیدها اعمال شد:
فقط صفحه‌های عمومی بدون ورود، یک درخواست در هر سه ثانیه برای هر میزبان، توقف با هر نشانه‌ی
مسدودی، و بازنشر نکردن چیزی جز تصویر کوچک و خلاصه با ذکر منبع. <Adr n="0011" />

## crawl مؤدبانه

<Steps>
  <Step title="robots.txt پیش از هر URL">
    `PoliteFetcher` برای هر URL و هر hop تغییر مسیر robots.txt را با protego چک می‌کند. خود
    robots.txt هم snapshot می‌شود. پاسخ ۴xx به robots.txt طبق RFC 9309 یعنی «بدون محدودیت»؛ این مورد
    برای `s3gw.shab.ir` (پاسخ ۴۰۳ از S3) ثبت و به مالک گفته شد.
  </Step>
  <Step title="یک درخواست هم‌زمان برای هر میزبان">
    دست‌کم ۳ ثانیه بین دو درخواست با jitter، یا Crawl-delay اگر بیشتر باشد. backoff روی ۴۲۹ و ۵xx با
    احترام به `Retry-After`.
  </Step>
  <Step title="توقف هنگام مسدودی">
    رگبار ۴۰۳ یا نشانه‌ی captcha پلتفرم را `BLOCKED` می‌کند و اجرا متوقف می‌شود. هیچ تلاش دوباره با
    header دیگر، proxy یا ابزار پنهان‌کاری وجود ندارد؛ ادامه فقط با تصمیم مالک (`crawl run …
    --after-block`).
  </Step>
  <Step title="معرفی خود">
    user agent نام ربات و راه تماس را می‌گوید (`CRAWL__CONTACT` در `.env`). cookie نگه داشته
    نمی‌شود. تنها شباهت به مرورگر header استاندارد `Accept` است، چون جاباما بدون آن صفحه‌ی بدون آگهی
    برمی‌گرداند.
  </Step>
  <Step title="snapshot از هر پاسخ">
    بدنه، وضعیت، headerهای انتخاب‌شده (بدون cookie) و زمان دریافت، content-addressed در blob store.
    حالت پیش‌فرض `CRAWL__MODE=offline` است و اجرای زنده پرچم صریح می‌خواهد.
  </Step>
</Steps>

## از snapshot تا کاتالوگ

parse تابع خالصی از snapshot است: adapter هر پلتفرم بدون I/O صفحه را می‌خواند و یک `ParsedListing`
(زبان مشترک ingestion و catalog) برمی‌گرداند. `make reparse` کل کاتالوگ را بدون یک درخواست شبکه
از snapshotها دوباره می‌سازد؛ تستی که socket را مسدود می‌کند این را تضمین می‌کند و دو بازسازی
پشت‌سرهم hash یکسان دارند.

داده‌ی آشفته‌ای که adapterها و نرمال‌ساز با آن کنار می‌آیند (هر مورد یک تست جدولی است؛ بیش از
۱۰۰ حالت):

- **واحد پول:** جاباما ریال منتشر می‌کند و شب تومان. هر adapter واحد پلتفرم خودش را می‌داند و
  `Money` همیشه ریال صحیح است؛ نمایش به تومان.
- **«صفر یعنی تعیین‌نشده»:** جاباما برای قیمت آخر هفته، تعطیل، نفر اضافه و امتیاز از `0` به معنای
  «تعیین نشده» استفاده می‌کند. این‌ها به «نامعلوم» تبدیل می‌شوند، هرگز به رایگان یا امتیاز صفر.
- **تقویم:** API تقویم شب دو شکل پاسخ دارد و روزها را با ماه شمسی کلید می‌زند. شب‌های
  `disabled` جاباما نمی‌گویند رزرو شده‌اند یا بسته، پس «در دسترس نیست» ذخیره می‌شوند.
- **متن فارسی:** ی و ک عربی، ارقام فارسی و عربی، نیم‌فاصله و فاصله‌ها؛ نرمال‌ساز idempotent است و
  با property test چک می‌شود.
- **مکان:** فیلد محله‌ی جاباما همیشه خالی است؛ نام‌ها از gazetteer دست‌چین `config/gazetteer.toml`
  (۱۱۷ مکان) resolve می‌شوند: فقط نام‌هایی که در داده دیده شده، بدون حدس غلط املایی.

## برداشت هم‌زمان سناریوها

مقایسه‌ی دو پلتفرم فقط وقتی معنا دارد که تقویم و قیمت هر دو در یک بازه‌ی کوتاه دیده شده باشند.
`crawl capture` تقویم همه‌ی آگهی‌ها را در یک پنجره دوباره برمی‌دارد. برداشت ۱۲ مهر: جاباما ۲٬۹۸۷ از

## خط لوله‌ی عکس

<Diagram name="photo-pipeline" caption="از عکس پلتفرم تا شواهد تطبیق و برچسب‌های تصویری" />

- **فقط بایت‌های لازم:** برای هر آگهی پنج عکس پوشش یک بار و مؤدبانه دانلود می‌شود. هر عکسی که به
  کاربر نشان داده می‌شود مستقیم از CDN خود پلتفرم بار می‌شود، پس چیزی برای نمایش کپی نمی‌شود.
- **pHash و dHash** برای کپی تقریباً یکسان و برای وزن «فراوانی در سند»: عکسی که در چند آگهی آمده
  (مثلاً عکس تبلیغاتی یک مجتمع) وزن کمی می‌گیرد.
- **DINOv2-small محلی** برای شباهت مقاوم به برش. در benchmark روی ۸۷۲ عکس و ۶۰۰ پرسش، recall@1
  برابر ۱٫۰ بود، در حالی که pHash برش ۷۰٪ را فقط در ۳۵٪ موارد پیدا کرد. embeddingهای API
  (gemini-embedding-2) همه‌ی کپی‌ها را پیدا کردند ولی ویلاهای نامرتبط را شبیه‌تر دیدند (صدک ۹۹
  شباهت ۰٫۸۳ در برابر ۰٫۶۶). <Adr n="0012" />
- **یک بار محاسبه:** embedding برای هر (hash محتوا، شناسه‌ی مدل) ذخیره می‌شود؛ اجرای دوباره چیزی را
  دوباره حساب نمی‌کند.
- **SigLIP 2** برای برچسب‌های صفر-نمونه (استخر، جکوزی، جنگل، باربیکیو، منظره‌ی دریا، شومینه)، با
  آستانه‌ای که برچسب‌های مالک تعیین می‌کند. شرح در [حقیقت‌سنجی](/docs/truth-check).

<Callout kind="info" title="چرا عکس‌های اصلی شب">
  تصویرهای کوچک شب برش ۴:۳ هستند و برای عکس‌های عمودی pHash را می‌شکنند (فاصله‌ی ۲۰ تا ۳۲ بیت). پس
  عکس اصلی شاهد تطبیق است، حتی اگر از قاعده‌ی «حداکثر ۸۰۰ پیکسل» بزرگ‌تر باشد؛ این استثنا در
  ADR-0008 ثبت شده است.
</Callout>

## حریم خصوصی و بازنشر

- نام نظردهنده‌ها ذخیره نمی‌شود؛ شماره‌ی تلفن هم. نام میزبان فقط برای تطبیق است.
- snapshotها و عکس‌ها هرگز وارد git نمی‌شوند. fixtureهای تست کوتاه و بدون داده‌ی شخصی‌اند.
- رزرو همیشه روی خود پلتفرم انجام می‌شود؛ هر صفحه پیوند مستقیم به آگهی اصلی دارد.

## بازتولید

```bash
make crawl P=jabama            # پیش‌فرض: بازپخش snapshotها، بدون شبکه
make crawl P=jabama LIVE=1     # crawl زنده (CRAWL__CONTACT لازم است)
make crawl-status P=jabama     # وضعیت صف frontier
make reparse                   # بازسازی کاتالوگ و hash عکس‌ها از snapshotها
make crawl-metrics             # ترافیک هر میزبان با فاصله‌ی اندازه‌گیری‌شده
make report                    # پوشش سناریوها و resolve شدن مکان‌ها
```
