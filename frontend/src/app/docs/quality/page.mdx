## لایه‌ها

| لایه        | ابزار                                      | چه چیزی را تضمین می‌کند                                                                                                           |
| ----------- | ------------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------- |
| دامنه       | pytest، hypothesis                         | منطق خالص: پول و بازه، تقویم شمسی، موتور قیمت (پوشش شاخه‌ی ۱۰۰٪)، قاعده‌های حکم، خوشه‌بندی مقید؛ پوشش کل دامنه ≥ ۹۵٪              |
| application | pytest با fakeها                           | use caseها روی adapterهای حافظه‌ای و `FakeLLMProvider` قطعی؛ dry-run با صفر فراخوانی                                              |
| قرارداد     | fixtureهای کوتاه هر پلتفرم                 | parser هر adapter روی صفحه‌های واقعی کوتاه‌شده و بدون داده‌ی شخصی                                                                 |
| معماری      | import-linter و تست معماری                 | جهت وابستگی، خلوص دامنه، نبود نام پلتفرم در هسته، نبود نویسه‌ی نامرئی؛ هر قاعده با fixture شکسته                                  |
| یکپارچگی    | testcontainers با Postgres و PostGIS واقعی | مهاجرت‌ها، repositoryها، صف، قیدهای پایگاه داده (یک آگهی از هر پلتفرم)                                                            |
| فرانت‌اند   | Vitest                                     | قالب‌بندی، client API، جدول وضعیت ROADMAP در برابر گزارش‌ها                                                                       |
| E2E         | Playwright با Chrome                       | منبع ده عدد تصادفی هر صفحه، حذف برچسب جستجو، صفحه‌کلید تقویم، نبود اسکرول افقی در ۳۷۵ پیکسل، نقشه‌ی آفلاین، همه‌ی مسیرهای مستندات |
| دسترس‌پذیری | axe در E2E                                 | هیچ خطای جدی یا بحرانی روی صفحه‌های محصول و مستندات                                                                               |
| smoke       | Playwright                                 | ۵۰ آگهی و ۵۰ ویلای دوپلتفرمی نمونه بدون خطای صفحه یا کنسول                                                                        |

## قراردادهایی که خودشان تست‌اند

- **ROADMAP و پورتال یکی‌اند:** جدول‌های وضعیت ROADMAP از `frontend/src/content/milestones.ts` و
  گزارش‌های `reports/*.json` تولید می‌شوند و یک تست Vitest اگر ROADMAP از آن‌ها عقب بماند شکست
  می‌خورد (`make roadmap` بازتولیدش می‌کند).
- **نمودارها با منبعشان یکی‌اند:** `npm run diagrams:check` در `make lint`.
- **OpenAPI و client تایپ‌شده:** `make openapi-check` اگر schema و typeها از هم جدا شوند شکست می‌خورد.
- **نسخه‌ی prompt:** تستی hash هر قالب prompt را نگه می‌دارد؛ تغییر قالب بدون بالا بردن نسخه شکست
  می‌خورد، پس کش هرگز پاسخ قالب قدیمی را برای قالب تازه سرو نمی‌کند.
- **رازها:** تست‌های repr و لاگ و پیام خطا، و gitleaks در pre-commit.

## دسترس‌پذیری و راست‌به‌چپ

- سند `lang="fa"` و `dir="rtl"` دارد؛ کد، شناسه‌ها و محور عددی نمودارها چپ‌به‌راست‌اند.
- پیوند «پرش به محتوا»، حلقه‌ی focus روی هر عنصر تعاملی، و کارت منبع با Popover بومی که با Escape بسته
  می‌شود و focus را برمی‌گرداند.
- رنگ هرگز تنها حامل معنا نیست: هر وضعیت و حکم آیکن و متن دارد.
- هر جدول پهن درون کارت خودش اسکرول می‌شود، نه کل صفحه؛ E2E در عرض ۳۷۵ پیکسل این را چک می‌کند.
- `prefers-reduced-motion` همه‌ی انیمیشن‌ها را خاموش می‌کند.

## فرمان‌ها

```bash
make lint               # ruff، mypy strict، import-linter، tsc، eslint، prettier، نمودارها
make test               # واحد و معماری (پوشش دامنه ≥ ۹۵٪) و Vitest
make test-integration   # Postgres واقعی در کانتینر یک‌بارمصرف
make test-e2e           # Playwright و axe روی برنامه‌ی در حال اجرا
make test-smoke         # ۵۰ صفحه‌ی نمونه
make quality-report     # همه‌ی بالا، با نتیجه در reports/quality-<date>.json، و بازسازی ROADMAP
make perf-report        # تأخیر API در reports/performance-<date>.json
make ci                 # lint و test و test-integration
```
